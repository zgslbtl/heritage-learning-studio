# 完成后重新下载与前端安全发布

已完成账号沿用原班级入口和原邮箱登录，保留原参与者和 run，直接进入双语作品下载页。该页只读取本人的 `/api/student/portfolio`，不请求同学作品或修改实验进度。未完成账号继续使用原阶段页面。

下载页支持两轮作品 PDF、浏览器打印另存 PDF、每轮原图及 UTF-8 文字说明。PDF 先生成 Blob，再由学生点击实际下载链接；图片、字体、模块或渲染等待有时限，失败时保留其他下载方式。原图仍经已有文件鉴权接口，完成后不会公开图片。

## 长时间打开页面的兼容性

Vite 页面可能在打开数小时后才懒加载 PDF 模块。部署时删除历史哈希文件，会使旧页面加载失败。`/assets/*` 必须直接作为静态文件处理：不存在时返回 404 与 `no-store`，不能回退为 `index.html`；HTML 使用 `no-cache`，现存哈希资源可使用 immutable 缓存。

更新静态文件时：

1. 备份当前完整静态目录、配置、源码及镜像。
2. 将新 `frontend/dist` 合并到旧静态目录，保留所有历史 `/assets`。可使用 `python3 scripts/publish_frontend_assets.py frontend/dist STAGED_WWW`；它会拒绝同名不同内容的资源，并最后原子替换入口。
3. 构建包含合并结果的持久镜像。`Dockerfile.caddy` 支持 `--build-arg WEB_RUNTIME_IMAGE=PREVIOUS_CADDY_IMAGE`：以已核验的前一镜像为基础，COPY 会保留此前哈希文件。若当前容器已临时恢复过旧资源，须额外将这些资源加入镜像，不能仅依赖前一镜像。
4. 对正在进行实验的环境，先复制资源，再原子替换入口；配置经 `caddy validate` 后用 `caddy reload` 加载。纯前端更新无需重启 API、数据库或 Caddy 容器。新镜像也须保留同一合并目录，以便未来重启。
5. 核对旧 PDF 模块仍返回 JavaScript、新资源哈希一致、缺失资源返回 404、原班级链接可解析、完成账号可读取本人两轮作品。

不要清理参与者数据来修复下载，也不要用旧数据库覆盖更新期间的新作答。回退时恢复前一入口和配置，保留新旧静态资源及新增数据。

## 验证范围

自动回归覆盖完成账号在班级冻结后退出重登、原 run/作品保留、未完成账号阶段不变、下载页只读请求、PDF 失败替代入口、图片超时及静态发布碰撞保护。实际浏览器验收应使用隔离测试作品生成并保存 PDF，同时检查窄屏版式。生产验收只读真实作品；临时鉴权会话按明确 token 哈希清理。
