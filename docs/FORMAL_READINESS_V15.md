## 1. 已冻结、不再需要决策的 v1.5 参数

- 流程：登录 → K0 → 操作说明 → T1 → K1 → K2 → T2 → K3 → 体验问卷 → 互评 → 作品广场 → 完成。
- T1 24 分钟、T2 20 分钟，总约 94 分钟。
- G1=A,X→Y；G2=A,Y→X；G3=B,X→Y；G4=B,Y→X；T2 所有人 Standard AI。
- T1 六字段；T2 开放说明；图片失败可提交文字。
- HLSF `hlsf-v1.5.0`，只用于 T1 B；T2 完全关闭。
- 互评：每人 6 件、每件 6 名评者、3 个 1–5 维度；匿名、不能自评。
- 社交：全班 T2 作品、评论可多条、不显示热度；**个人完成自己的 6 件互评后进入作品广场，不等待全班**。
- 登录：PolyU 邮箱 + 班级专属链接。
- 班级：最多 30；所有已进入 user 结束 T2 后自动开放互评，无现场手动开放。
- 分组：现有班内 G1–G4 平衡块分配，首次登录绑定。
- 不做 MaxDiff。

## 2. P0 阻断项（正式采集前必须完成）

### 2.1 伦理、同意与数据治理

- [ ] 伦理/IRB 批准。
- [x] T2 作品提交处用底部小字提示“提交即表示同意将今天的学习数据用于后续研究”；提交时自动写入 `consent_future_research=true`、`consent_recorded_at`、`consent_version=work-submit-v1`。
- [ ] 使用伦理批准的正式知情说明/措辞；该底部提示只覆盖“后续研究使用”，不替代完整 participant information sheet。
- [ ] 撤回/退出、数据删除、保留期限。
- [ ] PolyU 邮箱明文的 DPIA；备份/管理员访问视为个人数据。
- [ ] 外部 AI Provider 数据处理、跨境、是否训练、故障/暂停规则。
- [ ] 馆藏图片、学生作品、未来公开的版权/授权。
- [ ] 四班统一知情说明、弃权/设备故障处理。

### 2.2 正式研究材料

- [ ] 两件文物 Evidence Pack：高清图、来源、事实、证据、不确定性、专家审核。
- [ ] 事实/推断/设计想象边界与来源 ID。
- [ ] 统一产品 Brief/类别；两件文物的难度与迁移距离审核。
- [ ] 正式 T1 任务说明、T2 开放任务说明。
- [ ] 全部内容非 demo；production readiness 通过。

### 2.3 K0–K3

- [ ] 每件文物独立知识蓝图：事实识别 2、历史功能 1、文化关系 2、证据判断 1；K0/K1 约 6 题 10–12 分。
- [ ] K2/K3 平行短版；K2 在 T2 前，K3 在 T2 后。
- [ ] 标准答案/评分键；不向学生反馈。
- [ ] 专家内容效度审核；Pilot 检查难度/区分度/天花板/前测效应。
- [ ] K0 是否加入极简设计经验项已定稿。
- [ ] 测评期间服务端锁定 AI/资料/创作（平台已具备）。
- [ ] 若正式协议要求限时，需增加 K0–K3 计时/自动保存/超时提交；当前只记录整段耗时。

### 2.4 T2 评分与过程编码

- [ ] 4×0–3 量规（文化理解、关系转译、情境适应、证据论证）专家审核并冻结锚点。
- [ ] 至少 2 名盲评者；20% 训练样本；ICC/一致性方案。
- [ ] 评分者不知道 A/B；作品/说明统一展示顺序。
- [ ] 过程编码（SE/ES/RM/CR/ER）操作定义与双编码方案。
- [ ] 预注册主要结局、缺失/缺席处理、多重检验策略。

### 2.5 协议冻结与审计

- [ ] `ProtocolVersion` 记录 HLSF 版本、模型/provider、采样参数、知识包 hash、互评量表版本、随机分配算法/seed。
- [ ] `ai_calls` 或调用日志记录 provider/model_id/prompt_version/knowledge_pack_sha256/sampling。
- [ ] 导出分配结果（class/group/condition/artifact order）与算法版本。
- [ ] 协议激活后禁止静默改提示词/模型/题库；任何变更新建协议版本。
- [ ] 旧 v1.0/v1.5 开发数据与新正式数据集分离。

## 3. v1.5 平台功能缺口（正式前必须补）

|---|---|---|
| 作品展示 | 所有有效提交 T2 自动进互评/广场 | 已确认不需要人工审核；保留技术有效性过滤 |
| 社交开放（个人级） | 学生自己完成 6 件后进入 social；已由测试覆盖 | 已确认保留个人级，不增加班级级 social gate；Pilot 记录早进入者与仍在互评者的并存情况 |

| 缺席/数量不足分配 | 自动按 N、有效作品数、A/B 数量分配；不要求手动补分配 | 若现场出现异常，记录 batch config；不手工改 DB |

## 5. Pilot 与正式启动

1. 专家审核（文物、K 题、量规、HLSF、六字段）。
2. Pilot 12–20 人：T1/T2 时长、题量、Prompt、图片延迟、互评负担、评分分布、导出。
3. 修正并冻结 v1.5 最终参数。
4. 四班 dry run：30 人/班、真实 Provider、闸门、缺席、备份。
5. 预注册、伦理批准、正式内容上线。
6. 正式 120 人（或按实际出席人数记录偏离）。
