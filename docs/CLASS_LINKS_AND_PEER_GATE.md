# 班级链接与自动互评闸门运行说明

日期：2026-11-06  
适用：四个班依次进行的正式 workshop，每班最多 30 人。

2026-11-08：`study`部署也开放内部班级0；班级0使用个人固定互评快照并持续接受新用户，不受下述正式班全班闸门约束。独立`beta`部署仍只开放班级0。两种部署中的正式/内部班规则以班级ID区分。

## 1. 规则

- 每个班（class 1–4）有独立入口链接：`/join?token=...`。
- 链接绑定班级；学生打开后班级锁定，不能自行改班。
- 学生首次用包含 `polyu` 的邮箱进入时创建 user；同邮箱再次进入恢复原 user。
- 该班互评是否开放，只看**该班所有已进入 user 的 T2 是否都已结束**，不要求固定 30 人。
- 没来/请假的学生不会创建 user，因此不会阻塞该班。
- 每个班 user 数仍然不能超过 30。
- 全班 T2 结束后，服务端**自动**冻结作品、生成互评批次并开放；不需要管理员现场点“开放互评”。正式班级的互评池包含 T1 和 T2 两轮最终作品，目标每件 6 个评分、每人 12 件。
- 开放瞬间冻结班级成员；之后新邮箱不能用该链接加入（409 `class_closed`），已有 user 可恢复。

## 2. T2 “结束”的定义

```text
Round.finished_at 非空
或 T2 deadline 已过（服务端按 timeout 结束）
```

- 学生主动“保存并进入 K3” → 结束。
- T2 倒计时结束 → 结束。
- 图片失败不影响结束。
- T2 超时但 `product_name`/`open_statement` 不完整：该 user 的 T2 算结束，但作品不进入互评池；后台会显示有效作品数少于已结束人数，不阻塞全班。
- 如果某个 user 进入后长期停在 T2 之前、既不完成也不超时，闸门会继续等待；这属于异常账号，需要另行处理，不是手动开放互评。

## 3. 课前

1. `/admin` 登录研究者后台。
2. “研究总览” → “班级链接与自动互评闸门”。
3. 为 class 1 生成链接；只把链接发给 class 1 学生。
4. 学生打开链接后班级锁定，输入 PolyU 邮箱进入。
5. 检查该班“已进入”人数是否与现场人数一致；缺席学生不会创建 user，不需要处理。

## 4. 课中

- 互评闸门卡片实时显示：
  - 已进入 user 数；
  - T2 已结束数；
  - 有效作品数（T1 + T2）；
  - 当前状态（收集中/已开放）。
- T2 完成前，学生完成问卷后会进入“等待全班完成 T2”页面；不会看到任何互评作品。
- 最后一个 user 的 T2 结束时，系统自动：
  1. 冻结班级成员；
  2. 生成该班互评批次；
  3. 学生等待页自动出现匿名作品。
- 管理员不需要点击开放按钮，只需观察卡片状态。

## 5. 四个班依次进行

- class 1 的 gate/batch 与 class 2 完全独立。
- class 1 互评进行时，class 2 可以用自己的链接开始 T1/T2；class 2 学生仍只看到自己的阶段。
- class 2 的互评只在 class 2 所有已进入 user 完成 T2 后自动开放。
- 作品、评分、点赞、评论全部按 `class_id` 隔离。

## 6. 常见情况

| 情况 | 系统行为 | 研究者动作 |
|---|---|---|
| 29 人班，29 人全部完成 T2 | 自动开放 29 人互评 | 无需操作 |
| 30 人班，30 人全部完成 T2 | 自动开放 30 人互评 | 无需操作 |
| 30 人班，29 人完成，1 人还在 T2 | 继续等待 | 等待该学生完成/超时；不要催促系统“开放” |
| 30 人班，1 人进入后长期不操作 | 继续等待 | 按现场预案处理异常账号；当前系统不提供手动开放 |
| 某学生 T2 超时、作品不完整 | 不阻塞闸门；作品不进池 | 在研究记录中标记；其作品不会被评分 |
| 开放后新邮箱用链接进入 | 409 `class_closed` | 说明该班互评已开始；不再新增 user |
| 学生刷新/重登 | 等待页/互评页恢复 | 无需操作 |
| 两个班同时进行 | 各自独立 gate/batch | 按班级分开管理 |

## 7. 数据与审计

新增表：

- `class_entry_links`：班级链接元数据（只存 token hash；可撤销/轮换）。
- `class_peer_gates`：每班闸门状态、成员冻结时间、开放时计数、批次 id。
- `class_peer_gate_events`：自动开闸事件与 counts。

导出新增：

## 8. 严格性边界

- 链接解决“班级绑定/误选班级”，不验证邮箱是否属于该班；当前登录不是 SSO。
- “全班”是动态集合：链接下已经创建 user 的人。没来的人不创建 user，因此不参与等待。
- 若需要严格核对 30 个指定姓名，需要另行增加 roster/allowlist；本次不改变登录方式。
- 开放后班级成员冻结；迟到且尚未创建 user 的学生无法再加入该班互评。
