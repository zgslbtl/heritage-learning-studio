## 1. 冻结结论

凡 v1.3 与 v1.5 存在差异的地方，**一律采用 v1.5**，不再保留 v1.3 的旧参数作为并行方案。

| 项目 | 采用 v1.5 | v1.3 旧方案（不再采用） |
|---|---|---|
| 总体流程 | 登录 → K0 → 操作说明 → T1 → K1 → K2 → T2 → K3 → 体验问卷 → 同伴互评 → 模拟 Instagram → 完成 | 同类流程但部分时长/环节不同 |
| 条件设计 | 首次登录固定 T1 条件 A/B；T2 所有人 Standard AI | 相同原则，但细节按 v1.3 排程 |
| 组含义 | G1=A,X→Y；G2=A,Y→X；G3=B,X→Y；G4=B,Y→X | 同方向，但 v1.3 另有预生成清单等要求 |
| T1/T2 时长 | T1 24 分钟；T2 20 分钟；建议总流程约 94 分钟 | T1 26 分钟；T2 23 分钟；总约 90 分钟 |
| T1 右栏 | 产品名称、类别/用途、目标受众、设计概念、1 张概念图、六字段说明 | 同方向（v1.5 更具体） |
| T2 右栏 | 产品名称/简短概念、概念图、一个开放作品说明框；无六字段、无四阶段 | 同方向（v1.5 更具体） |
| HLSF | `hlsf-v1.5.0` 产品设计四阶段；仅 T1 B | v1.3 提示文本 |
| 同伴互评 | 每人 6 件、每件 6 名评者、3 个 1–5 维度、可选评论 | 每人 4–6 件、2 道评分题 + 可选分享意愿 |
| 社交 | 全班 T2 作品（含自己）、可多条评论、无热度显示；**个人完成自己的 6 件互评后即可进入** | 平衡分配 4–6 件、每件最多 1 条评论 |
| 登录 | PolyU 邮箱 + 班级专属链接 | 匿名编号 |
| 分组实现 | 复用现有 G1–G4 班内平衡块分配；首次登录绑定 | 预生成分层随机清单 |
| 班级人数 | 每班最多 30；按实际已进入 user 动态开闸（29 人也可） | 固定 30 人班 |
| 互评开放 | 全班所有已进入 user 的 T2 结束后自动开放；无现场手动开放 | 未规定自动闸门 |
| MaxDiff | 不做 | 不做 |

## 2. 明确被 v1.5 取代的 v1.3 参数

以下不再作为正式协议参数：

- 不再采用“每人 4–6 件、2 道评分题”的互评方案；正式为 **6 件/人、3 个维度**。
- 不再采用“平衡 4–6 件作品流、每件最多 1 条评论”的社交方案；正式为 **全班 T2 作品流、评论可多条**。
- 不再采用 v1.3 的 **T1 26 / T2 23 / 总 90 分钟**；正式为 **T1 24 / T2 20 / 总约 94 分钟**，Pilot 可再调。
- 不再采用匿名编号登录；正式保留 **PolyU 邮箱 + 班级专属链接**（但伦理/DPIA 必须覆盖邮箱明文）。
- 不再要求“预生成分层随机清单”作为唯一实现；正式采用现有 **班内 G1–G4 平衡块分配 + 首次登录绑定**，但必须导出/冻结分配结果与 seed 记录。
- 不再采用 v1.3 的 4–6 件社交曝光平衡；正式为 **本班全部有效 T2 作品**，曝光以 social_views 记录。
- 社交开放采用**个人级**：学生完成自己的全部分配互评后即可进入作品广场，不等待全班其他同学完成互评。该行为已由 `test_peer_social` 覆盖（first 已进入 social_feed 时 second 仍在 peer_assessment）。
- 互评分配采用 `peer-v2-balanced`：按实际班级人数 N 和有效作品数自动计算；N>=7 时每人/每件最多 6，N<7 时每人评 N-1 件；N=29、N<30、部分缺席或作品不足时仍保证不评自己、不重复；不是固定 30 人模板。
- 29 人时仍按 G1–G4 四人 block 分配：7 个完整 block + 1 个 partial block，四组约为 8/7/7/7；A/B 与 X/Y 约为 15/14（由 partial block 决定）。K0/K1、K2/K3 题本按组内 AB/BA 交替，组内为 4/4 或 4/3。
- 作品不做人工审核，技术性提交成功的 T2 作品进入互评/广场；评论不做事前审核，仅保留应急隐藏接口。
- T2 最终作品提交时底部以小字提示“提交即表示同意将今天的学习数据用于后续研究”；不设置勾选框，提交即记录 `consent_future_research=true`。字段为 `runs.consent_future_research`、`consent_recorded_at`、`consent_version=work-submit-v1`。
- 互评曝光以 `peer_impressions` 记录实际展示时间与停留时长；assignment 不等于 exposure。
- 不再把 v1.3 的“互评 4–6/2 题”作为平台回归标准；平台回归以 v1.5 的 6/3 为准。

## 3. 仍然适用、未被 v1.5 取代的内容

- T1/T2 均为文创产品设计；T2 不得调用 HLSF。
- T1 六字段：文化特征、历史功能与社会意义、资料与证据、文化延续、文化转译/再情境化、创新与设计理由。
- K0/K1 对应 T1 文物；K2/K3 对应 T2 文物；K2 必须在 T2 之前。
- K0–K3 使用测评引擎；答题时服务端锁定 AI、资料、创作；不显示答案反馈。
- 互评在 K3 与体验问卷之后；不能评自己；匿名作品编号；不显示作者/条件/已有评分/热度。
- 模拟 Instagram 不连接真实 Instagram，不伪造互动；点赞/评论/曝光真实写入数据库。
- 作品不做人工审核：所有技术性提交成功的 T2 作品进入互评和作品广场；不设置 approve/reject 流程。
- 评论不做事前审核：学生评论直接显示；保留研究者隐藏不当评论的应急接口，但不作为正式流程要求。
- 不做 MaxDiff；只导出经审核/授权的匿名作品资产供未来研究。
- 图片生成失败不阻塞文字提交。
- 协议、文物、题目、作品、提示词、模型配置需要版本化并可审计。

## 4. 本次冻结不能替代的正式实验前置条件

即使 v1.5 参数已冻结，正式采集前仍必须完成：

1. 伦理/IRB 批准；consent 页面与各授权范围；撤回/删除/保留期限。
2. 两件正式文物 Evidence Pack、版权/授权、专家审核。
3. K0–K3 正式题本、答案键、知识蓝图、专家内容效度审核。
4. T2 4×0–3 量规、双评分者培训、ICC、盲评流程。
5. 协议级冻结：HLSF 版本、模型/采样参数、知识包 hash、随机分配结果、量表版本。
6. 互评曝光与 N=29/缺席/作品不足的自动分配已实现。**作品人工审核、评论审核 UI、班级级社交开放均明确不需要**；个人级 social 开放是研究组确认的正式行为。作品级未来公开/导出的授权字段仍可在需要时补充，但不阻塞互评/作品广场。
7. Pilot 12–20 人；30 人真实 Provider 压测；Docker/Caddy/HTTPS/备份恢复验证。
8. 预注册、缺失数据/缺席处理、分析计划。

## 5. 版本控制

- 本记录冻结后，任何影响 A/B 比较、T1/T2 任务、K0–K3、互评/社交规则、时长、模型或提示词的修改，都必须：
  1. 新建协议版本；
  2. 更新 `docs/V15_CHANGE_REPORT.md` 与平台交接文档；
  3. 如已开始正式采集，不得在同一协议内静默变更。
- v1.3 文档保留为历史研究方案；不再作为平台实现的并行参数来源。
