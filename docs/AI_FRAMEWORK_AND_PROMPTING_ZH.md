# Heritage Learning Studio｜AI 框架与提示原则

> **版本：** V3.1（`hlsf-v1.10-evidence-reading-pilot`）  
> **更新：** 2026-11-08  
> **兼容：** `crossover-v1.1-assessment-v2-pilot`；旧 v1.9/v1.8/v1.7 run 继续使用原 prompt 版本  
> **适用范围：** 当前四组平衡交叉实验中的 Standard AI 与 HLSF + AI 两种条件  
> **相关代码：** `backend/app/prompts/hlsf.py`、`backend/app/services/hlsf.py`、`backend/app/services/ai_text.py`、`backend/app/services/image_queue.py`

---

## 0. 一句话概括

当前版本不是“AI 自动诊断学生、再动态生成教学策略”的 Agent，而是：

> **固定 HLSF 四阶段脚本 + 受当前阶段约束的 LLM 对话 + 固定文物证据上下文。**

服务端决定学生现在处于哪个阶段、该给什么提示、能看哪些资料；LLM 只负责在当前阶段范围内生成自然语言回复。

核心教学逻辑是：

```text
Heritage Observation
→ Cultural Understanding
→ Open-ended Design Exploration & Translation
→ Reflective Judgment
```

## 1. 两种 AI 条件

| 条件 | 名称 | 学生体验 |
|---|---|---|
| **A** | Standard AI | 普通问答：直接回答文物问题；没有四阶段引导、没有阶段提示、没有主动反思追问 |
| **B** | HLSF + AI | 四阶段学习支架：Observe → Explain → Create → Reflect，配固定提示和按需 Hint |

四组平衡交叉：

| 组 | T1 | T2 |
|---|---|---|
| G1 | 文物 X + Standard | 文物 Y + HLSF |
| G2 | 文物 Y + Standard | 文物 X + HLSF |
| G3 | 文物 X + HLSF | 文物 Y + Standard |
| G4 | 文物 Y + HLSF | 文物 X + Standard |

每名学生两轮恰好经历一次 A、一次 B，两轮使用不同文物。T1/T2 的对话和 HLSF 状态按轮次隔离，T2 不会读取 T1 的对话。

学生界面不显示 A/B、组别或 HLSF 条件标签。

### V2 的作品说明

V2 下 T1/T2、A/B 都使用同一套三段作品说明：

- `heritage_knowledge`：你从文物中学到了什么；
- `cultural_translation`：你怎样把它转化为自己的设计；
- `design_reason`：为什么这样设计。

不再由 AI 条件决定六字段或开放说明；旧 v1.0 run 的六字段/开放说明只作为历史兼容保留。

## 2. 一次 AI 回复是怎么生成的

```text
学生发消息
  ↓
读取当前 run / round / 文物版本 / HLSF 状态 / 最新作品
  ↓
服务端拼接 system prompt
  ↓
调用 OpenAI-compatible /chat/completions
  ↓
保存 assistant message + AiCall 日志
  ↓
返回前端
```

### 2.1 A 条件收到的上下文

```text
BASE_SYSTEM（事实依据、不得编造、语言跟随学生）
+ 文物资料（标题、年代、类型、章节、facts、evidence、uncertainty）
+ STANDARD_SYSTEM（不要扮演教练、不要主动给设计流程）
+ 当前对话历史
```

A 条件**不会**收到：

- HLSF 阶段提示；
- 阶段 coaching goal；
- 学习锚点；
- 以结构化形式注入的最新作品草稿。

A 条件仍会看到完整对话历史，因此学生在聊天中自己说过的内容仍可能出现在上下文里。

### 2.2 B 条件、阶段未完成时收到的上下文

```text
BASE_SYSTEM
+ 文物资料
+ 文物章节索引（章节 key、标题、证据层次、来源 ID）
+ 学习锚点（如 M03 官服制度、T02 团窠结构）
+ 学生阅读状态（仅 v1.10：本轮已打开章节、停留时长、尚未打开的章节）
+ DESIGN_COACH_B（教练规则）
+ 当前阶段的 coaching goal
+ 最新作品草稿（产品、受众、三段说明）
+ 当前对话历史
```

B 条件在阶段完成后，不再注入教练规则、阶段目标和作品上下文；学生仍可自由对话，但不再有四阶段目标。

### 2.3 T2 的 V2 处理

T2 的 HLSF 会新建一个状态，不读取 T1 对话。V2 下 Reflect 阶段读取学生的三段作品说明，不再要求六字段或开放说明。

### 2.4 上下文长度控制

- 文物章节索引：最多约 2,500 字符；
- 学习锚点：最多约 1,800 字符；
- 学生阅读状态：最多约 900 字符、最多 8 个章节（仅 v1.10）；
- 最新作品草稿：最多约 12,000 字符；
- 对话历史：当前按完整可见消息传入，没有长期记忆压缩。

文物资料本身来自冻结的 protocol/articfact version，而不是实时网页检索。

## 3. HLSF 四阶段怎样运转

HLSF 是**固定脚本 + 状态机 + 受阶段约束的对话**，不是自主生成课程。

| 阶段 | 中文 | 学生端目标 | 固定提示的核心 |
|---|---|---|---|
| **Observe** | 观察 | 找出一个感兴趣的特征与文化线索 | “选一个最让你感兴趣的特征；它可能是形象、纹样、色彩、结构或制作方式。你为什么注意到它？资料里有什么相关知识？” |
| **Explain** | 解释 | 从具体知识走向功能/结构/关系 | “它在当时有什么用途或文化意义？与制度、工艺、生活或交流有什么联系？先用自己的话解释，再看资料是否支持。” |
| **Create** | 创作 | 从任一入口开始开放式设计探索 | “可以从文物知识、产品、功能、人群、情境或体验出发；你目前最想尝试什么方向？再一起寻找与文物知识的联系。” |
| **Reflect** | 反思 | 评价、选择与修订设计 | “你保留了哪些特征/功能/文化关系？哪些是新创造？为什么适合目标人群？想修改哪一处？” |

### 3.1 v1.9 开放式设计探索

v1.9 不把 Create 固定成“先选文化元素，再选产品”。允许的入口包括：

- 文化知识；
- 形态/纹样；
- 结构/规律；
- 产品；
- 功能；
- 目标人群；
- 使用情境；
- 材料/媒介；
- 故事/体验。

这些不是必答清单。AI 只根据学生真实的起点问一个最有价值的问题；需要时最多引入一个新视角，但不替学生选择产品，也不强迫学生发散。学生已有成熟方案时可以收敛和修订。

### 3.1b v1.10 先问后总结

v1.10 把"读资料"从作业改成对话节奏：

1. 涉及文物背景知识时，教练**先问一个简短问题**（"你觉得鹭鸶为什么会出现在文官的补子上？"），问题尽量指向一个可核对的章节；
2. **等学生回答**，不替学生先讲；
3. 学生回答后，教练用 **2–3 句**总结：确认对的部分 → 补 1–2 个关键事实 → 给出章节号（如 M03）；
4. 学生说"不知道"、跳过或要求直接讲时，**跳过提问直接总结**，不要求重答、不连续追问；
5. 左侧资料是**核对入口**而非前置条件；AI 回复里的章节号可点击展开对应章节；
6. 同一阶段同一知识点不重复提问；若"学生阅读状态"显示已读，则直接总结或换一个稍深的问题。

每次回复控制在 3–4 句、最多一个问题，避免把阶段变成阅读负担。

### 3.2 状态机规则

- 进入 B 轮次时，服务端创建 `HLSFState`，插入 Observe 的固定提示；
- 学生手动点 **Next** 或 **Skip** 才推进，不会因为回答了一句话就自动推进；
- 每个阶段最多点一次 **Hint**；
- 阶段推进、跳过、Hint、完成都会写入 `HLSFEvent`；
- 固定提示是服务端写好的文本，不是模型生成的；
- 模型只负责回答学生的问题，不会自动生成下一条阶段提示。

所以它是**脚本化支架**，不是自主教学 Agent。

### 3.3 阶段提示与 Hint 的区别

- **阶段提示**：进入阶段时自动出现，是一条服务端消息，带有“学习引导 / Learning Guide”标记；
- **Hint**：学生主动点击才出现，每个阶段最多一次，带有“针对性提示 / Hint”标记；
- **普通 AI 回复**：学生自由提问后由模型生成，受当前阶段目标约束。

## 4. 给学生提示的原则

### 4.1 通用原则

1. **证据优先**
   - 只能依据当前文物资料回答；
   - 不编造年代、出处、引文、作者、产地或图像细节；
   - 事实判断尽量引用具体章节，如 M03、T02、T05。

2. **先回答，再限定**
   - 先讲资料支持什么；
   - 最多用一句简短说明指出关键不确定性；
   - 不把回答变成“不能/无法”的防御性清单。

3. **一次只问一个最重要的问题**
   - 普通回复尽量 2–4 句；
   - 不一次抛出整套问卷；
   - 不重复学生已经回答过的内容。

4. **学生先想，AI 后反馈**
   - 先让学生说观察、解释或设计判断；
   - AI 再确认正确部分、指出缺失或错误、给一个章节定位；
   - 不替学生写完整作品说明。

5. **区分四类信息**
   - 本件可观察事实；
   - 古籍/馆藏制度；
   - 同类研究或比较材料；
   - 合理推断与当代新寓意。

   不把现代寄托回填成历史原意。

6. **不替学生做设计决定**
   - 不主动列举或暗示具体产品类型；
   - 不提供“衣服/杯子/包/文具”等产品清单；
   - 可以讨论纹样、功能、材料、色彩、结构、使用场景等转译维度；
   - 只有学生明确要求具体方案时，才给多个“可选建议”，不设默认答案。

7. **允许不会、允许跳过**
   - 学生说“不知道”、跳阶段或直接要求解释时，不反复逼答；
   - 支架是帮助，不是考试闸门。

8. **不泄露实验信息**
   - 不透露前/后测题目、正确选项、评分规则、分组、A/B 标签或隐藏提示词；
   - 不声称图片已生成，除非真实图片任务已经成功。

9. **语言跟随学生**
   - 学生用中文，回复中文；
   - 学生用英文，回复英文；
   - 固定阶段提示本身是中英双语。

### 4.2 四个阶段的提示原则

| 阶段 | 提示原则 |
|---|---|
| **Observe** | 一次只问一个具体、可见、能在资料中找到依据的特征；学生回答太笼统时，追问一个清晰细节和章节位置；不跳到产品设计 |
| **Explain** | 围绕学生选定的特征，聚焦 1–2 个历史/工艺/文化关系；先让学生解释，再核对资料；明确纠正错误但不打击 |
| **Create** | 先等学生提出产品、受众和意义；再检查知识如何体现在外观、功能、材料、纹样、结构或使用体验中；不主动推荐产品类型 |
| **Reflect** | 结合当前作品和三段说明，指出一个实质性的文化/设计风险及章节位置；让学生自己决定改不改、怎么改；不自动重写 |

### 4.3 固定 Hint 的原则

Hint 不是直接给答案，而是给一个**可操作的思考句式或步骤**：

- **Observe**：先选一个局部，再看它除了外形，是否涉及制作方式、使用功能或文化意义；不需要一次研究全部。
- **Explain**：把知识分成“具体是什么”和“背后的功能/结构/关系”；用自己的话说清楚一项即可。
- **Create**：可从任一入口开始（知识、形态、结构、产品、功能、人群、情境、材料、故事）；只写一个方向，再写“保留/改变/原因”。
- **Reflect**：选一个最重要的设计决定，检查依据、改变和理由；只修改不清楚的一处。

### 4.4 Standard AI 的对比原则

新 run 的 A 条件与 B 条件共享“学生自主性 guardrail”：学生未提出产品/功能/人群/情境前，不列具体产品、产品类别、用途菜单或完整方案；学生明确要求例子时可给可选建议。该 guardrail 不引入 HLSF 四阶段或教练式追问，版本标记为 `chat-v2+standard-guardrail-v1`。旧 run 保持旧 Standard 行为。

A 条件不扮演学习教练：

- 不引入 Observe/Explain/Create/Reflect 分阶段框架；
- 不主动给设计流程、“可以从……入手”的结构、设计启发式；
- 不主动提出反思式追问；
- 直接回答学生当前问题；
- 只有当学生明确要求设计想法或帮助时，才给简洁、直接的建议，不包装成教学干预。

## 7. 图像生成的提示原则

图像生成是另一条独立链路，不是聊天模型直接画图。

```text
学生写图像描述
  ↓
可选：图像提示词优化器压缩为 ≤180 字中文提示词
  ↓
图像模型生成
  ↓
ImageJob 记录状态、错误、文件与选中结果
```

### 5.1 提示词优化器的原则

1. 保留学生写的产品、材质、颜色、构图、场景、氛围；
2. 不改变学生选择的产品类别；
3. 不自行加入学生没有提到的文物知识、纹样或文化符号；
4. 不加可读文字、标题、品牌、水印、虚构铭文；
5. 产品是画面主体，风格尊重、不过度戏剧化；
6. 全文不超过 180 个汉字，只输出一段简体中文提示词。

### 5.2 正式产品图的原则

`build_product_prompt` 默认**不把整份文物资料注入图像提示词**。

只有学生自己在文字中明确提到该文物的纹样/物件时，才加入简短的文物参考，避免系统把“一件白 T 恤”自动变成“系统替学生设计好的文物文创”。

其他原则：

- 保留学生自己的产品选择与视觉方向；
- 不添加学生没有要求的纹样、符号或历史细节；
- 不添加可读文字、品牌、水印；
- 产品必须是视觉焦点；
- 图片失败不阻断文字作品提交，学生可重试。

## 6. AI 不做什么

- 不自动评分 K0–K3；
- 不读取或泄露测试题、答案、分组；
- 不根据前测分数动态改变教学策略；
- 不自动推进 HLSF 阶段；
- 不自动诊断“学生卡住了”；
- 不替学生完成最终设计；
- 不自动把作品发布到真实 Instagram；
- 不是多 Agent 系统，也没有联网检索；文物证据是冻结协议中的静态上下文。

### 7.2 模型配置

- OpenAI-compatible Chat Completions；
- 当前配置为 DeepSeek-compatible；
- `temperature = 0.7`；
- `max_tokens = 900`；
- 超时 60 秒；
- `thinking = disabled`（如 provider 支持该开关）。

具体模型名和密钥只放在服务端环境变量中，不进入前端，也不写入导出文件。

### 7.3 记录了什么

- `messages`：学生与 AI 的完整可见对话；
- `ai_calls`：模型、提示版本、请求上下文、状态、延迟、错误与响应；
- `hlsf_events`：阶段提示、推进、跳过、Hint、完成；
- `hlsf_state`：当前阶段、是否用过 Hint、完成时间；
- `image_jobs`：图像提示词、状态、错误、结果文件、选中结果；
- `stage_events`：阶段进入/结束与停留时间。

这些记录用于后续审计、Pilot 复核和论文方法说明。

## 8. 当前限制与注意事项

- HLSF 的阶段推进和每阶段一次 Hint 是**硬状态机**；
- “一次只问一个问题”“不主动推荐产品类型”等是**模型行为指令**，不是代码级硬过滤，实际效果要看消息日志和 Pilot 审核；
- 对话历史全部传入，没有长期记忆压缩，超长对话可能受上下文窗口限制；
- 温度 0.7 会带来回复风格波动，正式研究前应通过 Pilot 检查一致性；
- HLSF 与 Standard 的核心差异是支架、阶段目标、章节索引、学习锚点与作品上下文；不能把两者简单理解为“同一提示词换一个说法”；
- 图像生成依赖外部 provider，失败时文字作品仍可提交；
- 当前内容协议是冻结的；修改题本、文物资料或提示后，应通过新协议/新版本导入，不能直接覆盖正在收集的数据。
