# HLSF 实验平台修改需求 v1.5（简洁开发版）

> **用途**：交给 Codex / 开发 Agent 的增量修改清单；不是重建平台方案。  
> **依据**：`PLATFORM_COMPLETE_GUIDE_ZH.md`（2026-11-06 交接版）及当前 HLSF v1.3 研究方案。  
> **说明**：以下“现状”来自交接文档，并非本次直接检查源代码。Agent 实施前须以实际代码和测试为准。  
> **原则**：保留现有基础、最小改动、可用优先、数据可追踪；文物正式资料、题库与互评内容稍后再填。

## 0. 严格保留，不要重构（P0）

- **登录不变**：继续使用现有 PolyU 邮箱＋班级入口、同邮箱恢复、`hls_student` Cookie、研究者 `/admin` 密码登录。保留现有参与者 UUID、Session、研究者数据查看方式；不要新增 SSO、验证码或新的登录步骤。（现有邮箱仅校验包含 `polyu`，属于已知正式研究风险；本次不顺带改造。）
- **技术栈与部署不变**：React/Vite、FastAPI、PostgreSQL/Alembic、Docker Compose、Caddy/TLS、同源 `/api`、现有单 API worker 机制，均不替换。
- **AI 调用不变**：继续复用现有 OpenAI-compatible 文本对话与图片生成 API 配置、服务端密钥、`ai_calls` 审计、图片任务队列、重试及错误展示。不得改为前端直连、静默 Mock 或自动切换模型。
- **存储与数据保护不变**：保留 `participants → runs → rounds` 主结构、聊天、版本保存、文物证据、图片、测评、事件日志、ZIP 导出；新增数据仅通过显式 Alembic 迁移扩展，不清空或覆盖历史记录。
- **版本冻结不变**：保留文物／题目版本、准备检查和协议冻结；新的 HLSF 提示词和分组逻辑也必须有版本记录。保持自动保存、刷新恢复、服务端计时、匿名导出。
- **视觉风格不变**：延续米白纸感、深蓝、金色点缀、简洁三栏工作台、中英辅助文案；只调整任务内容、结构与必要交互。

## 1. 首先修改实验分组与任务流程（P0）

- **停止旧的 A/B 两轮交叉实验**：不再让同一学生先后体验 A、B。新实验中，学生在首次登录时确定 T1 条件；**T2 无论来源组别，全部使用普通 AI**。
- 尽量复用现有 G1–G4 四组和班内平衡分配代码，只改变其含义：`G1 = A、X→Y`；`G2 = A、Y→X`；`G3 = B、X→Y`；`G4 = B、Y→X`。四班内尽量均衡；后端在 `rounds.condition` 记录实际条件，T1=A/B、T2=A。
- **只有两个创作任务**：`T1 = 文物知识理解＋文创产品 AI 共创`（包含知识学习与设计表达两部分）；`T2 = 新文物迁移共创`（两组普通 AI、开放式作品说明）。不再出现“第三个独立迁移创作 Task”。
- **调整服务端状态机**，新流程为：`登录 → K0 → 操作说明 → T1 → K1 → K2 → T2 → K3 → 体验问卷 → 同伴互评（6件定向评分） → 模拟 Instagram（全班30件自由互动） → 完成`。K0/K1 对应 T1 文物，K2/K3 对应 T2 新文物。**K2 必须出现在 T2 前**；旧版 `transfer` 问卷不能误当作 T2 创作。
- K0–K3 均复用测评引擎，当前可使用清楚标注的 **DEMO 占位题**；正式题目、答案键和专家审核资料后续再导入。答题时在服务端禁用聊天和创作接口，不显示答案反馈；完成后继续当前流程。
- 时间先按 **约94分钟建议流程** 布局，最终由 Pilot 调整：登录3、K0 6、说明3、T1 24、K1 5、K2 4、T2 20、K3 5、问卷4、互评8、作品流8、缓冲4（合计94分钟）。**互评与社交必须拆为两个独立阶段；题目和作品正式内容仍可先用明确标注的 DEMO 占位，不得伪造真实互动**。

## 2. T1：替换旧“短视频脚本＋关键帧”工作台（P0）

- **保持现有三栏**：左侧 `文物图片/简介/历史事实/证据/不确定性`；中间 `AI 对话`（仅 B 组显示 HLSF 四阶段引导）；右侧改为 `我的文创设计`。继续使用现有倒计时、保存状态、错误重试与日志。
- 右侧不再填写视频标题、短视频脚本。改为：**产品名称、产品类别／用途、目标受众、设计概念描述、1张产品概念图**。仍使用现有图片任务和额度机制；把图片提示词从“视频关键帧”改为“文化遗产文创产品概念效果图”，避免生成不需要的电影式画面。
- T1 必须有一份 **两组完全相同的六字段结构化作品说明**（可使用折叠区块减少界面负担）：①文化特征；②历史功能与社会意义；③资料与证据；④文化延续；⑤文化转译／再情境化；⑥创新与设计理由。每个字段可自由输入短文，自动保存；不做实时 AI 自动打分。
- 作品说明**由学生填写和提交**，允许参考 AI，但不让系统自动以 AI 输出覆盖学生记录；保存初稿／修改版本，便于后续研究编码。图片生成失败仍允许提交文字作品，并保留错误日志。
- A、B 使用同一文物资料、任务要求、六字段说明、模型与图片额度；**唯一教育干预差异**为 B 组额外启用 HLSF 引导。学生前台不出现 A/B 实验分组标签。

## 3. B组 HLSF：更新后台提示词，而不是重建 Agent（P0）

- 保留现有 `observe → explain → create → reflect` 四阶段、每阶段一条引导及最多一次按需提示的简洁交互。继续复用现有 `hlsf_states`、`hlsf_events`、阶段推进／跳过接口。
- 修改 `backend/app/prompts/hlsf.py`：删除旧版专门面向**短视频叙事**的“故事种子、叙事结构、历史侦探／微观场景／过程重建”主引导，替换为**文化知识理解与产品设计转译**的提示。提高 `HLSF_VERSION`，保留旧版本审计信息。
- 四阶段目标与简短示例：
  - **Observe**：请指出你观察到的两个文化特征；哪些是直接看见的，哪些只是猜测？
  - **Explain**：结合资料解释其中一个特征的历史功能、文化关系及来源；证据不足时明确说明。
  - **Create**：思考保留哪项文化意义、如何转化为现代产品的外观／功能／使用体验、为什么这样设计；不要只复制纹样。
  - **Reflect**：区分史实、解释与当代创作，选择一项值得修改的设计决策，最终由学生决定。
- B组 AI 日常回复以简洁、自然、一次最多一个关键追问为主；学生明确要求生成或修改产品概念时允许正常协助。**不得额外提供新史实或未授权证据**，两组共用历史准确性和不确定性底线。
- 新版 B 组上下文从当前学生的文化特征选择、六字段说明和最新设计草稿获取必要内容；不再注入旧的 short-video story seed / script coach。不得因缺失字段就假装学生已经填过。
- **T2 必须完全关闭 HLSF 策略**：不显示四阶段导航，不发送自动教育提示，不注入 B 组训练历史、六字段格式、文化转译教练或隐藏学习提示；仅保留与 A 组一致的基础 AI 与证据约束。学生主动向普通 AI 提问不受限制。

## 4. T2：新文物＋普通 AI 的开放式迁移任务（P0）

- T2 与 T1 使用**同一三栏工作台基础、同一产品概念图功能和基础模型**；自动加载另一件文物，不能再看到 T1 的私有对话。两组皆为 Standard AI。
- 右栏仅保留**产品名称／简短概念、产品概念图、一个大的开放式作品说明框**，提示语例如“请介绍你的设计，以及为什么这样设计”。**不显示六字段提问或四阶段阶段条**。
- 保留 T2 完整学生／AI 对话、资料访问、作品编辑版本和图片生成数据，以便研究判断学生是否主动关注文化证据、保留与转译关系、评价 AI 内容。
- T2 的主要评分在平台外进行，不开发复杂实时评分器；仅导出作品、开放回答、对话与生成记录，为未来盲评及统计分析留足字段。

## 5. K0–K3 与两类评价：互评和模拟 Instagram 必须独立（P1）

- **K0/K1/K2/K3**：先实现四个可配置测评时点／占位题本／正常提交与导出；以后在后台替换为正式文物知识题。复用单选、多选、简答、证据判断及 Likert，不需要开发新题型。
- **学生互评（Peer Assessment）单独页面**：K3 与体验问卷提交后，先进入「同伴评价」。每个班30人，推荐正式方案为**每人随机评价6件同班 T2 作品，每件作品接收6位同伴评分**；每班180条评分，四班理论合计720条；不能评价自己，同一评价者不能重复评价同一作品。数量是 Pilot 待验证参数，不是保证统计显著的数字。
- **互评分配必须均衡且盲评**：班内 A/B 理论上各15人，每人尽量分配**原 A 组3件＋原 B 组3件**，并让每件作品获得来自两个来源组、数量尽量平衡的评价；也尽量平衡 T2 文物 X/Y。学生界面只见匿名作品编号、作品图和作品说明，不显示作者姓名、A/B 条件、被点赞数和已有评价。正式分配在作品列表冻结后由服务端一次生成、保存版本，刷新／重登不重新洗牌。
- **互评表单尽量轻量**：每件作品依次评分3项，均为1–5级并显示简短清晰锚点：①文化信息表达是否清楚；②文物知识与设计选择的联系是否容易理解；③作品整体设计吸引力。保留可选的简短意见。**学生不是文物史实专家，互评分数不能代替文化准确性的专家盲评**；3项先分开分析，不预设为单一量表。
- **互评数据与缺失**：保存分配关系、作品与评者匿名ID、评分维度、作答时间、提交／缺失状态、量表版本；一人评价6件不等于有6个独立样本。无人提交或作品缺失时，显示明确空缺，不自动补造评价。可在研究者后台按规则补分配并留下日志；正式启用前做 Pilot 核查。
- **模拟 Instagram（作品广场）单独页面**：互评全部完成后开放。**每位学生可以看到本班全部30名学生的 T2 作品（包括自己的，但禁止给自己点赞或评论）**；自由浏览、给任意数量不同作品点赞／取消点赞、发表评论，不必强制每件都互动。不要连真实 Instagram，也不需要推荐算法、排行榜或关注系统。
- **社交浏览与数据**：班内作品按每名学生固定的随机顺序显示，避免固定首页位置优势；每件作品显示图片、名称、简短说明、匿名作品编号。点赞一人一作品最多一票，可取消并保留事件记录；评论可多条，记录评论者、作品、时间和内容，支持研究者隐藏不当内容。建议**评价和社交环节结束前不展示其他人的点赞总数／评论热度**，降低从众效应；若研究未来要公开热度，应单独设计条件。
- **社交数据不可等同评价分数**：单独导出作品曝光／打开记录、点赞、取消、评论、班级及作品匿名信息；作为探索性受欢迎程度指标。需考虑展示机会、位置、是否浏览、社交关系与同班熟悉度。对比 A/B 组时不能把点赞事件当作独立样本，也不能把喜欢程度等同于知识掌握。
- **目前开发边界**：互评与作品广场的**两个独立页面及数据接口占位**可先完成；分配规则、评分标签、互动开关可先用非生产 DEMO 配置。正式作品与评分项待研究者确定后再冻结；如果实施真实点赞／评分，必须保存真实事件，不能用静态假数据混入导出。
- **MaxDiff 不在平台内**：不加 Best–Worst 题、消费者选择集、BIBD、分析或页面。只保留后期导出**经审核且有授权**的作品图像、匿名作品 ID、文物类型和必要作品信息的能力，供将来另做消费者研究。

- 测评按 K0/K1/K2/K3 映射到明确版本，导出标识不得与旧 `pre_test/r1_test/post_test/transfer` 的语义混淆。允许新增小范围 stage/kind 枚举与新 Alembic 迁移；不重写测评引擎。
- 原研究者后台保留总览、材料配置、准备检查、详情与 ZIP 导出，仅更新任务名称、分组含义、阶段状态及新作品字段。为 peer 和 social 分别预留数据结构（例如 peer_assignments、peer_ratings、social_likes、social_comments、social_views）与独立导出；仅做最小数据读写和权限控制，不开发复杂社区后端。

- 在正式研究前继续使用非生产 DEMO 数据；**旧开发库已有历史测试 run 和协议锁定**，应在新分支／新测试数据库上验证，不覆盖旧数据。更新 readiness，正式启动时不允许仅凭占位题进入正式研究。

## 7. 开发顺序与验收标准

- **第一批 P0（先让核心研究跑通）**：①分组与服务端阶段调整；②T1/T2 产品创作右栏；③T1六字段／T2开放框；④B组提示词替换、T2关闭 HLSF；⑤K0–K3 占位测评；⑥作品与测评导出。
- **第二批 P1（预留未来内容）**：⑦互评单独页面与均衡分配／评分占位；⑧模拟 Instagram 单独作品广场与点赞评论占位；⑨后台作品审核／授权导出字段；⑩完善体验文案与移动端布局。
- **不做 P2／本次排除**：MaxDiff、实时公众发布、视频生成、多 Agent、自动迁移评分、复杂学习诊断、排行榜、支付／购买、社交推荐算法。
- **必须通过的回归**：现有邮箱／班级登录与恢复；四组平衡；T1 A/B 同模型和相同任务；T2 两组均无 HLSF Prompt；K0–K3 顺序和测评阶段禁止 AI；自动保存／恢复；图片队列与失败继续；刷新不乱跳；协议冻结；研究者详情与匿名导出；已有核心 API 不受破坏。
- **真实 Pilot 前检查**：单班约30人同时使用文本和图片 API 的实际排队、费用、超时；原版并发默认2，需测试而非假设可满足课堂时间；安全／伦理同意、数据保存与删除策略另行落实。

## 9. 互评分配与分析的最小统计约定（正式版本启用前确认）

- **建议数量：6件/人、6人/件**。每班30人时 `30 × 6 = 180` 条评分；四班120件作品共720条评分。这里的独立作品数量仍为120，不能把720条记录当作实验 N=720。
- **分配算法建议**：同班随机且平衡的有向评价网络，满足 `reviewer != author`、每位评者6件、每件作品6名不同评者、每人所评分作品原则上3件来自原A组和3件来自原B组。若全班有15名A和15名B且都提交有效作品，可以对每组建立固定随机顺序，用循环错位分配，确保评分次数守恒；不平衡、缺席、未提交时使用受约束补分配并记录偏离。每位评者看到的6件作品再随机排序。
- **信度先验不是保证**：在独立、可交换评分误差的简化假设下，多评分者均分信度估算 `R(k)=kρ/[1+(k-1)ρ]`。当单评分者信度ρ=0.20/0.30/0.40、k=6时，预计均分信度约0.60/0.72/0.80；这些是敏感性分析示例，不是本研究已测结果。正式 Pilot 需依据实际评分方差、评者严厉程度、完成率评估6件是否合适，若质量不足再调4/5/8件与任务时长。
- **优先分析**：以**作品**为单位计算各维度6人平均评分，报告分布、完成率、信度和与专家评分的相关；可采用前测／班级／文物调整的 A/B 比较作为次要探索分析。敏感性分析用**作品与评分者交叉随机效应模型**处理评者严厉程度，不能直接用720条独立 t 检验。互评发生于知识测验之后，不据此声称互评导致知识学习提高。
- **Instagram 分析**：按作品汇总独立点赞者人数、浏览机会、评论数；按班级及来源组探索差异，必要时采用考虑曝光及班级的计数／二项模型。此社交场景是同学间偏好，不应称为真实公众或消费者偏好，也不能替代后续独立 MaxDiff 研究。
- **依据与边界**：Falchikov & Goldfinch (2000), *Review of Educational Research*, DOI `10.3102/00346543070003287`；Xiong, Schunn & Wu (2023), *Journal of Computer Assisted Learning*, DOI `10.1111/jcal.12861`（指出通常3–5名评分者较合适，实际依情境变化）；Tong, Schunn & Wang (2022), *Studies in Educational Evaluation*, DOI `10.1016/j.stueduc.2022.101233`（评分者增加可能加重负担）。多评分者信度可参照 Spearman–Brown；社交从众效应参照 Muchnik, Aral & Taylor (2013), *Science*, DOI `10.1126/science.1240466`。以上文献不证明6是普适最优数，仍须 Pilot。
